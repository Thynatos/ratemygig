CRITICAL gotchas (verified against the code — do not skip):
- attendance RLS is OWNER-ONLY: policy "Users can view own attendance" is
  USING (auth.uid() = user_id) (002_rls_policies.sql line 86). Reading FRIENDS'
  attendance therefore requires the RPC to be SECURITY DEFINER with
  SET search_path = public (pattern in 013). Because SECURITY DEFINER bypasses RLS,
  the function MUST restrict the social graph to the caller: filter
  user_follows by follower_id = auth.uid() (keep the spec's p_user_id parameter for
  signature compatibility but do not let it enumerate arbitrary users' graphs;
  document this deviation in a migration comment).
- user_follows columns are (follower_id, following_id) — the followed user is
  following_id. attendance.status is the ENUM attendance_status ('planned','attended')
  with UNIQUE(user_id, event_id), so one row per friend per event (no dedupe needed).
- profiles already has display_name and avatar_url (001_initial_schema.sql) — join
  profiles on attendance.user_id for the RPC's display fields.
- EventCard is React.memo'd with an `event`-ONLY prop and is rendered from 6 places:
  DiscoverPage.tsx:236, ArtistDetailPage.tsx:109+121, VenueDetailPage.tsx:106+118,
  TrendingEventsSection.tsx:39, RecommendedEventsSection.tsx:51. The new friends
  prop MUST be optional (existing call sites and the 6 EventCard renders in
  features/components.test.tsx pass only `event` and must keep compiling/passing).
  Pages opt in by passing a pre-fetched slice of the Map — do NOT call the hook
  inside EventCard (zero extra queries per card is the acceptance bar).
- features/feed/components/FeedCard.tsx has its OWN local EventCard component
  (different component, `item` prop) — do not touch or confuse it with
  features/events/components/EventCard.tsx.
- MyGigsPage's `gigs` from useMyGigs(statusFilter) is TAB-FILTERED — on the
  'planned'/'attended' tabs it contains only that subset. Calendar export must
  include ALL planned + attended events: call useMyGigs() unfiltered for the
  export (same query key as the 'all' tab, so React Query dedupes there).
- SPRINTS.md says "useFriendsGoing test following the mocking pattern in
  follows.test.ts" — verified: follows.test.ts only tests QUERY KEY FACTORIES;
  no supabase-mocking pattern exists anywhere in the repo. Do NOT invent mock
  infrastructure. Instead: extract the row→Map grouping into a pure exported
  function (e.g. groupFriendsByEvent(rows)) and unit-test that + the query key
  factory, matching the existing key-factory test style.
- Validate the RPC response client-side with a Zod schema (add to
  shared/validation/schemas.ts) + validateRpcResponse() from shared/lib/utils.ts
  — this is the established M4 pattern for all RPC call sites.
- ical.ts must be pure and dependency-free — take the UID domain as a parameter
  with a default (e.g. 'ratemygig'), do NOT read window.location inside the lib,
  so tests are deterministic.
